# 計測と改善の記録

負荷試験、SQL、コード、nginx、設定を変更前後で比較した記録を置きます。

## ファイル名

```text
YYYY-MM-DD-テーマ.md
```

例:

```text
2026-09-12-posts-index.md
```

## 基本の流れ

1. 対象API、環境、計測条件を固定する
2. 変更前を計測する
3. ログ、SQL、コードから仮説を一つ選ぶ
4. 一つだけ変更する
5. 正しさ、エラー、service状態を確認する
6. 同じ条件で再計測する
7. 採用または不採用を決める
8. 戻し方を確認する

標準では変更前後を各3回計測します。最初の確認実験や時間が短い日は1回でもよいですが、1回だけであることを記録します。

書式は[計測テンプレート](../templates/benchmark-experiment.md)を使います。日次ログには要約と、この記録への相対リンクだけを残します。

利用者名を含む絶対パス、マシン名、SSH情報、private IP、秘密情報、大量の生ログは保存しません。比較する数値と判断に必要な行だけを要約します。
