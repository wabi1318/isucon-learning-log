## 始める前に知っておくこと

`ss`は、Linuxが管理している通信の接続先や待受状態を表示するコマンドです。

| 部分 | 意味 | 今回の目的 |
|---|---|---|
| `ss` | socket statistics | 通信の状態を表示する |
| `-l` | listening | 待受中だけを表示する |
| `-n` | numeric | 名前へ変換せず番号で表示する |
| `-t` | TCP | TCP通信だけを表示する |
| `-p` | processes | 確認できる範囲でプロセス情報を表示する |

最初に見る列は二つです。

- `State`: `LISTEN`なら接続を待ち受けている
- `Local Address:Port`: そのマシン内で待ち受けているIPアドレスとポート

`Process`欄は、実行利用者の権限によって空になる場合があります。空でもポートが待ち受けていないとは判断しません。まずロードマップ指定のコマンドをそのまま実行し、表示結果を確認します。

## 実技2: Lima VMで待受ポートを表示する

- 目的: 設定上の想定を、実際のLinuxの状態と照合する
- 目安時間: 10分
- 実行場所: 練習リポジトリのルートからLima VMへ接続した後
- 実行前の予想: `:80`と`:3000`の行が`LISTEN`になるか考える
- 利用者が行う操作: VMへ接続し、ロードマップ指定コマンドを実行する
- コマンド:

練習リポジトリのルートで実行します。

```sh
task vm:ssh
```

VMへ接続できたら実行します。

```sh
ss -lntp
```

- 出力のどこを見るか: `State`と`Local Address:Port`。まず末尾が`:80`または`:3000`の行だけを見る
- 成功の判断: `ss -lntp`を実行し、二つのポートが`LISTEN`か、表示されないかを事実として伝えられる
- 失敗の判断: VMへ接続できない、コマンドが見つからない、または出力のどの列を見るか分からない
- 状態が変わるか: SSH接続は始まるが、VMやserviceの状態は変わらない。`ss`は表示だけを行う
- 困ったとき: 全出力を保存せず、見出しと`:80`、`:3000`を含む行だけを伝える。見つからない場合は「見つからない」と伝える

観察後は次でホストへ戻ります。

```sh
exit
```

- 状態が変わるか: 変わらない
- 困ったとき: 設定は予定、`ss`は現在の状態と考える

## よくある間違いと確認方法

| 間違い | 確認方法 |
|---|---|
| `-lntp`を一つの名前だと思う | `-l`、`-n`、`-t`、`-p`へ一つずつ分ける |
| `LISTEN`を通信中だと思う | 新しい接続を受け付けられる待受状態と説明する |
| `Process`欄が空なのでプロセスがないと考える | 権限で表示されない可能性があるため、`State`とポートを先に確認する |
| 設定ファイルだけで現在の状態を断定する | `ss -lntp`の実行結果と分けて記録する |
| 全行をそのまま共有する | 見出しと`:80`、`:3000`の行だけを要約する |
