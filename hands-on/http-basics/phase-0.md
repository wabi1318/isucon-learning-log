## 資料を見る前の小さな問題

現在の理解だけで次の三問へ答えます。

1. HTTPリクエストとHTTPレスポンスは、誰から誰へ送られるものだと思いますか。
2. GETとPOSTは、何が違うと思いますか。
3. 200、404、500は、それぞれ何を表すと思いますか。

分からない問題は「分からない」と答えて構いません。まだ調べません。

## 予想後に説明する前提知識

利用者の回答後、Codexが次を一つのHTTP通信として説明します。

```text
クライアント
  → HTTPリクエスト
  → サーバー
  → HTTPレスポンス
  → クライアント
```

- リクエスト: クライアントがサーバーへ送る依頼
- レスポンス: サーバーがクライアントへ返す結果
- GET: 主に情報を取得する依頼
- POST: 主に情報を送って新しい処理を依頼する操作
- ステータスコード: サーバーが処理結果を三桁の番号で示したもの
- 200: 成功
- 404: 対象が見つからない
- 500: サーバー内部で処理に失敗した

GETでもサーバー側の実装次第で状態が変わる場合があります。ここではロードマップに必要な大まかな役割だけを扱います。

## 資料を閉じて行う確認

1. HTTPの往復を、クライアント、リクエスト、サーバー、レスポンスの順で説明する。
2. GETとPOSTの大まかな違いを説明する。
3. 200、404、500を成功、対象なし、サーバー内部の失敗へ対応させる。

## よくある間違いと確認方法

| 間違い | 確認方法 |
|---|---|
| リクエストとレスポンスの向きを逆にする | 最初に処理を依頼する側がクライアント |
| GETとPOSTを成功と失敗の違いだと考える | GETとPOSTは依頼の種類、成功と失敗はステータスで確認する |
| 404を通信できなかった状態だと考える | サーバーから404が返ったなら、HTTPレスポンスは受信している |

## ISUCONでどこに役立つか

ISUCONでは、リクエストが遅いのか、対象が見つからないのか、サーバー内部で失敗したのかをステータスと応答時間から分けます。HTTPの往復を区別できると、設定やコードを変える前に問題が起きた場所を絞れます。
