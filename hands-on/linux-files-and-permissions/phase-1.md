# Phase 1: 基本コマンドでファイルを調べる

## 今回できるようになること

次の三つを、学習ログ内の安全な対象で行います。

1. `pwd`、`cd`、`ls -la`で現在地と項目を確認する
2. `file`と`less`でファイルの種類と内容を調べる
3. `find`で検索場所を限定してファイルを探す

## 始める前に知っておくこと

- `ls -la`は、隠し項目を含む現在のディレクトリの一覧を詳しく表示します。
- `file`は、名前ではなく内容の特徴からファイルの種類を調べます。
- `less`は、ファイルを変更せずに画面ごとに読みます。終了は`q`です。
- `find`は、指定した場所の下から条件に合う項目を探します。

## 資料を見る前の小さな問題

次の目的に使うコマンドを、現在の理解で一つずつ答えます。

1. 今いる場所を知りたい。
2. 隠し項目を含めて一覧を見たい。
3. ファイルの種類を知りたい。
4. 長いファイルを画面ごとに読みたい。
5. 名前を条件にファイルを探したい。

分からない項目は「分からない」と答えて構いません。

## 実技1: 現在地、一覧、種類を確認する

- 目的: `pwd`、`ls -la`、`file`の役割を実際の出力で区別する
- 目安時間: 10分
- 実行場所: 学習ログのルート
- 実行前の予想: `study-status.md`と`hands-on`がそれぞれ何と判定されるか考える
- 利用者が行う操作: 現在地、一覧、二つの対象の種類を順に表示する
- コマンド:

```sh
pwd
ls -la
file study-status.md hands-on
```

- 出力のどこを見るか: `pwd`の現在地、`ls -la`の名前と先頭文字、`file`のコロンより右側
- 成功の判断: 三つのコマンドが、場所、一覧、種類のどれを確認するか説明できる
- 失敗の判断: 実行場所が違う、対象が見つからない、または三つの出力を同じ目的だと捉える
- 状態が変わるか: 変わらない
- 困ったとき: エラー全文ではなく、`pwd`の末尾のディレクトリ名と、見つからなかった対象名だけをCodexへ伝える

## 実技2: `less`でロードマップを読む

- 目的: 長いファイルを変更せずに開き、必要な場所を検索して終了する
- 目安時間: 10分
- 実行場所: 学習ログのルート
- 実行前の予想: 通常の画面へ戻るには何を押すか考える
- 利用者が行う操作: 第1週ロードマップを開き、`ps aux`を検索して終了する
- コマンド:

```sh
less roadmap/catch-up/week-01-linux-server.md
```

`less`の画面で次を行います。

```text
/ps aux
Enter
q
```

- 出力のどこを見るか: 検索後に`ps aux`を含む行へ移動するか
- 成功の判断: 対象行を見つけ、`q`で元のシェルへ戻れる
- 失敗の判断: ファイルを変更しようとする、検索文字が見つからない、または終了できない
- 状態が変わるか: 変わらない
- 困ったとき: `q`を一度押す。戻らない場合は画面下の表示だけをCodexへ伝える

## 実技3: `find`でREADMEを探す

- 目的: 検索範囲と名前を指定し、必要なファイルだけを探す
- 目安時間: 10分
- 実行場所: 学習ログのルート
- 実行前の予想: `README.md`が一つだけか、複数見つかるか考える
- 利用者が行う操作: 公開用の三つのディレクトリから`README.md`を探す
- コマンド:

```sh
find hands-on roadmap daily -name 'README.md' -print
```

- `hands-on roadmap daily`: この三つのディレクトリだけを探す
- `-name 'README.md'`: 名前が一致する項目だけを選ぶ
- `-print`: 見つけたパスを表示する
- 出力のどこを見るか: 各行が指定した三つのディレクトリ名のいずれかから始まること
- 成功の判断: 複数の`README.md`を見つけ、検索範囲と条件を説明できる
- 失敗の判断: 何も表示されない、学習ログの外を探す、または秘密情報を対象にする
- 状態が変わるか: 変わらない
- 困ったとき: 検索範囲を広げず、先に`pwd`で実行場所を確認する

## 実技4: `cd`と相対パスを確認する

- 目的: 現在地が変わると、相対パスの起点も変わることを確認する
- 目安時間: 5分
- 実行場所: 学習ログのルート
- 実行前の予想: `hands-on`へ移動後、`study-status.md`を指す相対パスを考える
- 利用者が行う操作: 一階層移動して現在地を確認し、元へ戻る
- コマンド:

```sh
cd hands-on
pwd
file ../study-status.md
cd ..
```

- 出力のどこを見るか: `pwd`の末尾と、`file`が対象をテキストファイルとして認識するか
- 成功の判断: `../study-status.md`が、移動前の`study-status.md`と同じファイルを表す理由を説明できる
- 失敗の判断: 別の場所へ移動する、または`..`を単なる文字として扱う
- 状態が変わるか: ファイルは変わらない。シェルの現在地だけが移動し、最後に元へ戻る
- 困ったとき: 追加で移動せず、`pwd`の結果をCodexへ伝える

## よくある間違いと確認方法

| 間違い | 確認方法 |
|---|---|
| `ls -ld`を実行したので`ls -la`も完了だと考える | オプションと表示対象が異なるため、指定された`ls -la`を実行する |
| `file`が内容をすべて表示すると思う | 種類の説明だけが表示されることを確認する |
| `less`を終了できず、シェルが止まったと思う | `q`で終了する |
| `find`を広い場所から実行する | `pwd`を確認し、検索場所を`hands-on roadmap daily`へ限定する |
| 相対パスの起点を固定だと思う | `pwd`を先に確認する |

## 資料を閉じて行う確認問題

目安は10分です。

1. 資料を見ずに、現在地、一覧、種類を確認する。
2. 第1週ロードマップを開き、指定した文字列を検索して終了する。
3. 学習ログ内から`README.md`を範囲限定で探す。
4. 各コマンドの出力のどこを見て成功と判断したか説明する。

## ISUCONでどこに役立つか

ISUCONでは、設定やログの場所を安全に探し、内容を変更せず読む必要があります。現在地と検索範囲を確認してから`file`、`less`、`find`を使えば、関係のない場所や秘密情報を不用意に開かずに調査できます。
