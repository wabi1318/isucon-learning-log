## 始める前に知っておくこと

### パス

- カレントディレクトリは、今いるディレクトリです。
- 絶対パスは`/`から始まり、どこにいても同じ場所を表します。
- 相対パスはカレントディレクトリを起点にします。
- `.`は現在のディレクトリ、`..`は一つ上のディレクトリです。

### 種類

`ls -l`の先頭一文字で、主な種類を見分けられます。

| 先頭 | 種類 |
|---|---|
| `-` | 通常のファイル |
| `d` | ディレクトリ |
| `l` | シンボリックリンク。別の場所を指す入口 |

### 所有者と権限

先頭一文字の後に、三文字ずつ三組の権限が並びます。

```text
- rwx r-x ---
  所有者 グループ その他
```

| 記号 | ファイルでの意味 | ディレクトリでの意味 |
|---|---|---|
| `r` | 内容を読める | 名前の一覧を読める |
| `w` | 内容を書き換えられる | 項目を追加・削除できる |
| `x` | プログラムとして実行できる | 中を通り、項目へ到達できる |

ディレクトリでは`r`だけあっても、その中の項目へ到達できるとは限りません。パスをたどるには、途中のディレクトリに`x`が必要です。

## 実技5: 誰が操作できるか判断する

- 目的: 種類、利用者、三組の権限をまとめて判断する
- 目安時間: 10分
- 実行場所: Codexとの会話
- 実行前の予想: 左から一文字、三文字、三文字、三文字に区切る
- 利用者が行う操作: 次の二例で、できる操作とできない操作を説明する
- コマンド: なし
- 出力のどこを見るか: なし
- 成功の判断: 利用者が所有者、グループ、その他のどれに当たるかを先に決められる
- 失敗の判断: 九文字を一組として読み、対象利用者を区別しない
- 状態が変わるか: 変わらない
- 困ったとき: まず対象利用者を一人に固定してから、その三文字だけを見る

例:

```text
-rw-r-----  sakaguchi sakaguchi  app.env
drwxr-x---  sakaguchi sakaguchi  current
```

次を説明します。

1. 利用者`sakaguchi`は`app.env`を読めるか、書けるか、実行できるか。
2. グループ`sakaguchi`に所属する別の利用者は`current`へ到達できるか。
3. その他の利用者は`current`へ到達できるか。

## よくある間違いと確認方法

| 間違い | 確認方法 |
|---|---|
| 相対パスを常に同じ場所だと思う | 先に`pwd`で起点を確認する |
| `rwx`を九文字まとめて読む | 三文字ずつ、対象利用者の組だけを見る |
| ディレクトリの`x`を「実行」とだけ覚える | 項目へ到達する権限だと説明し直す |
| 拡張子だけで実行可能と判断する | `ls -l`で`x`を確認する |
| 権限エラーを`chmod 777`で回避する | 利用者、所有者、必要な操作を先に特定する |

## ISUCONでどこに役立つか

ISUCONでは、設定、ログ、実行ファイル、serviceが異なる利用者で扱われます。パスと権限を読めれば、反映後にアプリが起動しない場合やログを読めない場合に、原因を短時間で切り分けられます。
