# 学習進捗を定例向けに報告する

現在の学習記録を読み、過大評価せず30〜60秒で読める報告へまとめる。

## 読む順番

1. `study-status.md`で最終更新日、現在地、ロードマップ実行状況、できること、次の一手を確認する。
2. `study-status.md`からリンクされた最新の日次ログを読む。証拠が不足する場合だけ、直近3件までの`daily/`を読む。
3. `reviews/queue.md`で要復習の内容と期限を確認する。
4. 完了判定にコマンド名や成果物の照合が必要な場合だけ、該当する`roadmap/catch-up/`を読む。

教材を読んだ事実や教材ファイルの存在を、利用者が学習した証拠にしない。

## 判定する

日次ログの実行証拠を`study-status.md`の要約より優先する。矛盾があれば、矛盾を短く示して日次ログに合わせる。

内容を次の四つへ分ける。

- `資料なし完了`: 目的、主要な操作、成功判断を資料なしで再現した証拠がある。
- `実行済み（要復習）`: 実行したが、ヒント、入力間違い、説明不足、再実行待ちのいずれかがある。
- `未実行`: 利用者の回答または記録から、まだ実行していないと確認できる。
- `未確認`: 実施したか判断できる記録がない。未実行と断定しない。

ロードマップに指定されたコマンドは、別のコマンドで完了扱いにしない。例えば、`ps -p`は`ps aux`の実行を兼ねない。Phase完了から日別メニュー完了を推測しない。

## 報告へ変換する

内部のPhase名より、利用者が実際にできるようになったことを先に書く。コマンド名は判断に必要な範囲で残す。

次の順で簡潔にまとめる。

1. 資料なしで完了した内容を、能力ごとに最大5項目で示す。
2. 実行済みだが要復習の内容を、未完了と混ぜずに示す。
3. 次に行う一手を1〜2項目だけ示す。
4. 定例でそのまま読める30〜60秒の報告文を付ける。

未実行項目の全一覧は、利用者が求めた場合だけ付ける。通常は直近の到達目標を妨げる項目だけを示す。

## 出力形式

```markdown
最新の学習記録はYYYY-MM-DDです。

### 資料なしで完了

- ...

### 実行済み・要復習

- ...

### 次に行うこと

- ...

### 定例でそのまま使える報告

> ...
```

該当項目がない節は省略する。利用者が報告文だけを求めた場合は、引用部分だけを返す。

## 正確さと公開範囲

- 「触った」「実行した」「資料なしで完了した」を区別する。
- ヒントが必要だった内容を「習得済み」「マスターした」と表現しない。
- 動的なPID、利用者名、マシン名、絶対パス、private IP、生ログを報告へ書かない。
- 実行証拠がない内容は推測せず、`未確認`とする。
- 学習記録の更新、Git操作、VM操作は、利用者が別途依頼しない限り行わない。
